# 0.2.0: PoC の検索ウィンドウを本実装として main に入れる

日付: 2026-10-27
ブランチ: `feat/unified-search`（元: `poc/multilingual-repository-search`、PR #1）

## 何のためか

PR #1 の 1 つの検索ウィンドウ（clone と GitHub / GHE を名前 > description > README > issue > 意味 > コードの順で探す）は、
2 回のレビューで修正必須の 4 件を直し終えている。残りは 2 回目のレビューが「推奨」「軽微」とした指摘で、
どれも main に出す前に直せる大きさ。利用者の依頼は「PoC のコード・設計・仕組みをもとに本実装し、PR → セルフレビュー → main へ merge（= リリース）」。

## ゴール

- 製品コード（`bin/`、`lib/`、`test/`、README、SKILL.md、CLAUDE.md、設計と調査の markdown）だけを main に入れる。
- 2 回目のレビューの残りの指摘のうち、1〜数行で直るものを直し、それぞれに回帰テストを 1 件付ける。
- 0.2.0 として npm に出る（main への push が CI の publish を起動する）。

## ゴールにしないこと

- `poc/`（Python の実験コードと約 20 万行の結果 JSON）と `docs/research/local-embedding-results.json`。PoC ブランチに残す。
- 意味検索のメモリ（約 4 GB）の根本対策（指摘 5-3）。README と `--help` に書くだけにする。
- ctrl-o でウィンドウを開いたままにすること（指摘 f）。CLAUDE.md の手動確認表は「the window reopens」で、今の動きと一致している。
- index.json の schema 番号（指摘 8-2）。形を変えるときに入れる。
- 古いランタイム・モデルの自動削除（指摘 13）。グローバルの 0.2 と npx の新しい版が同じキャッシュを使うと、
  互いの 1.2 GB を消し合い、毎日ダウンロードし直すことになる。残る方がまし。CLAUDE.md に「上げた人が消し方を書く」と残す。
- `publish.yml` で fzf を入れること（実装後に見送り）。ワークフローのファイルを変える push には `workflow` スコープのトークンが要り、
  この作業のトークンにはなかった。本物の fzf のテストは、今までどおり CI では skip される。

## 制約

- CLAUDE.md の不変条件すべて（I1〜I12）。特に I1（stdout は機械向けだけ）、I7（`--json` の形）、I9（実行時の依存を増やさない）。
