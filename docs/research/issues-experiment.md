問い: README と description に issue の本文を足すと、中国語の質問でリポジトリを見つけやすくなるか。
README で当たっていた質問を壊さないか。

## 条件

- モデル: Qwen3-Embedding-0.6B（前回の実験で最良）。比較として全文検索（lexical.py と同じ方式）。
- 索引は 2 種類で、同じ質問を両方に投げる。
  - **R**: description + README
  - **R+I**: description + README + issue（タイトル + 本文、open/closed とも。PR とコメントは除く）
- リポジトリの score は、そのリポジトリの chunk の cos の最大値（前回と同じ）。
- 対象: 前回の 26 リポジトリ + issue が 1 件以上ある自分のリポジトリ。
- 質問:
  - **issue 質問**: issue にだけ書かれていて README にはない内容を、別のエージェントが ja / zh / zh_nolatin で書く。原文の言い回しは写さない。
  - **README 質問**: 前回の 19 問 + 正解なし 5 問をそのまま使う。リポジトリが増えた分、前回より難しくなる。

## 非公開データの扱い

issue の大半は非公開リポジトリにある。

- 本文・質問・ベクトル・順位表は `~/Library/Caches/ghqcd-poc/issues/`（0700）に置き、git には入れない。
- この文書と git に載せるのは、件数と正解率などの集計値だけにする。リポジトリ名は公開リポジトリのものに限る。
- 収集のコードには、リポジトリ名を書かない（`gh` で毎回列挙する）。
