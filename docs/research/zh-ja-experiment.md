# 中国語→日本語 リポジトリ検索の実験

問い: 日本語だけで書かれたリポジトリ説明を、中国語の質問で翻訳なしに見つけられるか。

実施日: 2026-10-26。全表の元データは`poc/results/`、失敗例の全件は[report.md](../../poc/results/report.md)。

## 結論

**見つけられる。Qwen3-Embedding-0.6Bは、日本語のみの26件に対する中国語の用途質問19問をすべて1位で当て、英字の製品名を抜いた中国語でも19/19だった。** EmbeddingGemma 2も18〜19/19で僅差。BGE-M3は16〜18/19、E5 smallは英字なしで9/19まで落ちる。

- 漢字の一致だけに頼る全文検索は、中国語7/19、英字なし1/19。モデルの成績は共通の漢字や英字の製品名によるものではない。
- 実用上の推奨はQwen3 0.6B。原文コーパス（英語README中心、長文）でもただ1つ全言語19/19を保ち、似たgwq系ツールの区別でも崩れなかった。Gemma2は原文コーパスで似たツールを取り違えた。
- ただし**評価が小さく天井に当たっている**。19/19の95%信頼区間の下限は約82%。Qwen3とGemma2の優劣はこのデータでは決められない。
- 単発CLIの起動は**モデルではなくPython側が遅い**。プロセス起動から最初の結果まで6〜8秒、そのうち`import sentence_transformers`が約4秒。モデル読込は0.3〜1秒、2回目以降の検索は20〜25ms。ghqcdへ組み込むならこの実行基盤は使えず、MLX（先行実験で0.86秒）などの軽い経路か常駐プロセスが要る。

検索はquery embedding・全chunkとの比較・repo集約を含むwarm値（warmup 5回の後60回）。起動時間はOSのdisk cacheを消していない。Qwen3の起動の内訳（MPS、2回）: `import torch` 0.8〜1.0 s、`import sentence_transformers` 3.9〜4.6 s、モデル読込 0.6〜1.0 s、最初の検索 0.15〜0.56 s。CPUでも合計5.6 sで、遅さはPythonライブラリのimportが主因。

正しさの検査は全モデル合格: 次元が仕様どおり、全値が有限、単位norm（誤差1e-7）、同じ質問の単独とbatch 4の出力のcosineが0.9999999以上。Qwen3とGemma2はモデル同梱のST promptと設計のtemplateの一致をassertで確認した。

## 限界

- 規模が小さい: 26 repo、19問。上位2モデルは天井に当たっており、優劣・一般的な精度は言えない。
- 中国語の質問と日本語のみコーパスは、どちらも人手ではなくAIが書いた。コーパスは質問を見ていない別エージェントが書いたが、AIが書く整った説明文は実際の日本語READMEより検索しやすい可能性がある。中国語の質問はネイティブの確認を経ていない。
- 日本語の質問は先行実験の20問で、READMEを見ながら作られた探索的なもの。
- 日本語のみコーパスにも製品名・コマンド名の英字が29%残る。英字なしの中国語質問で、その影響をおおよそ切り分けた。
- 負例は5問だけ。棄却の閾値は決めていない。

## 設計からの逸脱

- BGE-M3の固定revisionにはsafetensorsがない（未マージの変換botのPRのみ）。公式の`pytorch_model.bin`を、transformersが既定で使う`torch.load(weights_only=True)`で読んだ。テンソル以外の復元を拒む読み方だが、「safetensorsのみ」の方針からは外れる。
- Gemma2はテキストしか使わなくても、processorの初期化にPillowとtorchvisionが必要だった。PoC環境にだけ追加した。
- 先行調査の対象26 repo・20問を引き継いだ。PR設計書の索引の差分更新・purge・lock・保存権限は、この問いに不要なため実装していない。

## 再現手順

```sh
cd poc
uv sync                            # uv.lockの固定環境
.venv/bin/python download.py       # 唯一の通信: 4モデルの固定revision
./run_all.sh                       # 通信遮断下: 全文検索、4モデル、起動時間×3
.venv/bin/python report.py         # 表を出力
```

`collect.py`はC1を公開GitHub APIから取り直す（固定blob SHA）。C2・質問は凍結済みファイルを使い、`run.py`・`lexical.py`は毎回manifestのSHA-256を照合する。
