# 多言語リポジトリ検索PoC タスクリスト

最終目標: 再現可能なPoC、モデル比較、日中検索の実測、設計20原則の審査を揃え、PRを作成してブラウザで開く。

## 作業条件

- ブランチ: `poc/multilingual-repository-search`
- ベース: `main` / `5f7f77a0dd311b65b0ca57f4e09a0f3a474e83ee`
- worktree: `npx gwqadd@0.3.5 -n --json --from main poc/multilingual-repository-search` で作成。
- ユーザー指定: brainstorming → writing-plans → executing-plans、ponytailを適用。
- リポジトリ本文と検索語の推論はローカル。実測には公開データのみを使用。
- 通常のghqcd、既存JSON、シェル連携、Node >=20.12、実行時npm依存なしの契約を維持。
- PoCは独立した検証領域に置く。mainへのpush・merge・リリースは今回の対象外。
- fzf-ghq-remoteの再利用はしない。以前の削除要求は認証不足で未完了のまま別件として記録。

## 設計の20原則

各項目について、設計時・実測後の判定と証拠を設計審査表に記録する。重大な未解決項目がある状態で実装完了とはしない。

| # | 原則 | 審査する具体的な内容 |
| --- | --- | --- |
| 1 | 目的と合否基準 | リポジトリを思い出す目的と測定指標が対応する |
| 2 | 最小の範囲 | PoCに必要な機能だけを作り、不要な常駐・抽象化を増やさない |
| 3 | 既存契約の保全 | 通常ghqcdの起動・出力・シェル・配布物を変えない |
| 4 | 責務の分離 | 取得・整形・embedding・保存・検索・評価の境界が明確 |
| 5 | 出典と正規形 | repo ID・ref・blob SHA・出典・取得日時へ戻れる |
| 6 | 入力検証 | 不正形式、巨大入力、パス逸脱、不正ベクトルを拒否する |
| 7 | モデル処理の正しさ | 公式のquery/document prefix・pooling・正規化を守る |
| 8 | 分割と情報保持 | 入力上限・重複・長文・日本語の分割と切り捨てを検査する |
| 9 | 差分更新と無効化 | 内容・モデル・前処理の変更で適切に再計算する |
| 10 | 保存の整合性 | 途中失敗・競合・次元不一致で既存索引を壊さない |
| 11 | 鮮度と権限 | 更新・削除・アカウント切替・権限失効の扱いが明確 |
| 12 | ローカル処理と最小収集 | 非公開本文を外部AIへ送らず、収集対象を限定する |
| 13 | 保存と削除の安全性 | 権限・バックアップ・索引削除・消去の限界を説明する |
| 14 | 供給元とライセンス | 固定revision、安全な重み形式、依存・利用条件を確認する |
| 15 | 検索データと命令の分離 | README/Issueを実行命令にせず、検索から副作用を起こさない |
| 16 | 言語横断の妥当性 | 中国語→日本語を翻訳・正解混入なしで評価する |
| 17 | 比較の公平性 | corpus・クエリ・token budget・量子化・集計方法の差を記録する |
| 18 | 時間と資源の測定 | 起動/通常時、P50/P95、索引時間、容量、メモリを分ける |
| 19 | 失敗とフォールバック | 通信断・モデル未導入・取得失敗・空結果を区別し、予算を制限する |
| 20 | 再現と独立レビュー | コマンド・環境・ハッシュ・テスト・レビュー・PRから追跡できる |
